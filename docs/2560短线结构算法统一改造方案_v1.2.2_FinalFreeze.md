## 1. 总体架构

系统拆分为两个独立模块：
- **模块 A：盘后选股**，T 日收盘后运行，输出 focus / watch / reject 与 final_score。
- **模块 B：早盘确认**，T+1 日 9:25 左右运行，仅对昨日 focus/watch 做升级或降级，不重新选股。

```text
T 日 17:00 盘后选股
  canonical_signal_engine
  -> structure_2560_analysis
        |
        v
T+1 日 9:25 早盘确认
  morning_confirm_engine
  -> morning_confirm_daily
        |
        v
T+1 日 9:30+ 人工 / 半自动观察
```

外部调用最小化 5 原则：
1. 批量接口优先，禁止 5000 票逐票循环。
2. 静态数据缓存到周。
3. 日频数据缓存到天。
4. 公告/研报仅对 focus 候选批量拉取。
5. 集合竞价只在 9:25 调用 1 次；若无候选则跳过。

## 3. 盘后模块 canonical_signal_engine

```text
Step 1：读取统一配置
Step 2：准备日线 / 30m / 5m 数据
Step 3：计算关键均线位置 ma_price
Step 4：计算 5/60 量能结构
Step 5：计算起爆段 recent_3d_pct
Step 6：计算 30m 压力位 high_20，排除当前K
Step 7：计算 5m 确认，仅信号时点前 6 根K
Step 8：计算 KDJ + MACD 右侧确认
Step 9：判定 market_state
Step 10：计算 hot_topic_strength + position_in_hot_topic
Step 11：执行硬性 Gate
Step 12：计算 final_score 并状态分层
Step 13：生成统一输出字段
Step 14：生成展示层文本，不提及集合竞价
```

### 3.1 硬性 Gate

- 价格距离关键均线不超过 pullback_max_pct
- 关键均线方向不能明显向下
- 5日均量 > 60日均量，或量能金叉兜底通过
- 未有效跌破关键均线
- explode_status != overheat
- 启用主线要求时，hot_topic_strength ∈ {strong, medium}

### 3.2 起爆段分层

| 状态 | recent_3d_pct | 处理 |
|---|---:|---|
| normal | ≤ 12% | 可进 focus |
| warm | 12% ~ 18% | 降权 / watch |
| acceleration | 18% ~ 20% | 仅 watch |
| overheat | > 20% | reject |
说明：8% 是 5/60 量金叉的常见伴随值，不再作为过热阈值。

### 3.3 30m / 5m / KDJ / MACD

```python
# 30m 压力位必须排除当前K
high_20 = max(high[-21:-1])

# 5m 确认只看 signal_time 前 6 根
confirm_window = bars_5m.before(signal_time).tail(confirm_5m_bars)
```

KDJ/MACD 不作为硬 Gate，但进入 intraday_score / structure_score。

### 3.4 market_state 与主线

| market_state | 条件示例 | environment_score |
|---|---|---:|
| rebound | 指数 ≥ +0.5%，涨停 ≥ 30，上涨比 ≥ 60% | 1.0 |
| oscillation | 指数窄幅波动，涨停 10~30 | 0.7 |
| correction | 指数 -0.5%~-1.5%，涨停少 | 0.4 |
| risk_off | 指数 < -1.5%，跌停明显 | 0.1 |

| hot_topic_strength | 条件 |
|---|---|
| strong | 板块涨幅前 5 + 涨停 ≥ 5 |
| medium | 板块涨幅前 15 + 涨停 ≥ 2 |
| weak | 上榜但不强 |
| none | 未匹配 |

| position_in_hot_topic | 含义 |
|---|---|
| leader | 板块核心 / 连板最高 / 涨停核心 |
| strong | 板块内涨幅前 20%，量价健康 |
| follower | 跟随 |
| edge | 蹭边 |

### 3.5 final_score

```text
final_score =
  0.30 * structure_score
+ 0.20 * volume_score
+ 0.20 * hot_topic_score
+ 0.10 * intraday_score
+ 0.10 * pressure_score
+ 0.10 * environment_score
```

## 4. 早盘模块 morning_confirm_engine

```text
Step 1：读取昨日 focus + watch
  若数量为 0：
    不执行任何外部调用
    写入 code='__skip__', morning_grade='skipped', missing_reason=MissingReason.NO_CANDIDATE
    流程结束
Step 2：加载今日集合竞价数据
Step 3：读取昨日竞价量或 avg5_auction_volume
Step 4：计算 auction_amplify_ratio / open_gap_pct
Step 5：计算 pre_market_state，仅作为辅助字段
Step 6：计算 morning_grade
Step 7：写入 morning_confirm_daily
```

### 4.1 集合竞价缺失值处理

```text
若 yesterday_auction_volume 缺失：
1. 若 auction_fallback_to_avg5 = false：
   morning_grade = hold
   missing_reason = MissingReason.FALLBACK_DISABLED
2. 若 true，使用 avg5_auction_volume：
   avg5 = 最近5个交易日中有效竞价量均值，不含当日
   有效天数必须 >= avg5_min_valid_days
3. 若 avg5 有效天数不足：
   morning_grade = hold
   missing_reason = MissingReason.AVG5_INSUFFICIENT
4. 若都不可用：
   morning_grade = hold
   missing_reason = MissingReason.AUCTION_MISSING_NO_AVG5
```

### 4.2 morning_grade 矩阵

| yesterday_status | 竞价 | gap_pct | morning_grade |
|---|---|---:|---|
| focus | 放量 | 0~3% | high |
| focus | 放量 | >3% | normal_cautious |
| focus | 不放量 | 任意 | hold |
| focus | 任意 | <-1% | downgrade |
| watch | 放量 | 0~3% | upgrade_high |
| watch | 放量 | >3% | normal_cautious |
| watch | 不放量 | 任意 | hold |
| 无候选 | - | - | skipped |

枚举强制：`{high, upgrade_high, normal_cautious, hold, downgrade, skipped}`，禁止出现 `normal`。

### 4.3 skipped 强约束

```sql
ALTER TABLE morning_confirm_daily
ADD CONSTRAINT chk_skipped_code
CHECK (
  (morning_grade = 'skipped' AND code = '__skip__')
  OR
  (morning_grade != 'skipped' AND code != '__skip__')
);
```

```python
def write_morning_confirm(row):
    if row['morning_grade'] == 'skipped' and row['code'] != '__skip__':
        raise ValueError('skipped 状态只能用于 __skip__ 代码')
    if row['code'] == '__skip__' and row['morning_grade'] != 'skipped':
        raise ValueError('__skip__ 代码必须使用 skipped 状态')
```

## 6. 外部调用流程

```text
Step 0：预算重置检查
  若 reset_at < CURDATE()：today_used=0, reset_at=CURDATE()
Step 1：计算 cache_key
Step 2：查 external_data_cache
  命中条件：ttl_hours IS NOT NULL AND ttl_hours > 0 AND expire_at > NOW()
Step 3：预算校验，超限则 budget_exceeded
Step 4：调用外部接口
Step 5：写 cache
  静态映射 ttl_hours=168
  日频数据 ttl_hours=24
  盘中实时 ttl_hours=NULL
  主动失效 ttl_hours=0 且必须走 invalidate_cache
Step 6：today_used += 1
Step 7：写 external_call_log
```

### 6.1 invalidate_cache

```python
def invalidate_cache(cache_key: str) -> bool:
    # 主动失效缓存，不删除，仅置 ttl=0 保留审计
    sql = (
        'UPDATE external_data_cache '
        'SET ttl_hours = 0, expire_at = NOW() '
        'WHERE cache_key = %s'
    )
    return execute(sql, (cache_key,))
```

```python
def render_missing_reason(reason: str) -> str:
    mapping = {
        'no_candidate_yesterday': '昨日无候选',
        'auction_data_missing_and_avg5_unavailable': '竞价数据缺失',
        'avg5_insufficient_history': '竞价历史不足',
        'auction_data_missing_and_fallback_disabled': '竞价缺失且兜底关闭',
    }
    if reason is None:
        return ''
    if reason in mapping:
        return mapping[reason]
    logger.warning(f'未知 missing_reason 取值: {reason}')
    return f'未知原因（{reason}）'
```
