## 一、评估结论总览

| 维度 | 评价 | 说明 |
|---|---:|---|
| 架构匹配度 | ⭐⭐⭐⭐ | 现有产品已覆盖“全市场扫描结果查看 → 候选池筛选 → 盘后决策报告”的主要链路，但尚未独立承载 REV-17 定义的“个股候选池深化报告层”和“早盘确认层”。 |
| 功能完整性 | ⭐⭐⭐ | 缺少早盘确认模块、个股独立报告入口，部分 v1.2.2 新字段尚未完整展示。 |
| 用户体验 | ⭐⭐⭐⭐ | 页面分层较清晰，但存在列表冗余、字段命名模糊、JSON 展示不够友好等问题。 |
| 对外合规性 | ⭐⭐⭐ | daily-selection.md 中仍出现“可执行交易”“开仓条件”“止损”等内部/交易化表述，需要按 v1.2.2 对外口径替换。 |
| 可演进性 | ⭐⭐⭐⭐ | 现有结果中心、观察池、标注页、盘后报告已经形成较好基础，适合继续扩展“个股报告”和“早盘确认看板”。 |

**总体结论：**

```text
当前产品端已经具备 v1.2.2 落地的良好基础，覆盖了全市场扫描结果查看、候选池筛选、历史信号追溯、人工标注复核、批次统计和盘后决策报告。

但当前产品形态仍以“列表查看 + 标注复核 + 盘后总报告”为主，尚未独立承载 REV-17 中定义的“个股候选池深化报告层”，也尚未提供 T+1 早盘确认看板。

因此，本次产品改进重点应聚焦三件事：
1. 补齐早盘确认展示；
2. 按 v1.2.2 对外口径清理 daily-selection.md；
3. 新增或内嵌“个股报告”能力，只对 focus/watch 生成 lite/full 报告。
```

## 三、与 v1.2.2 + REV-17 的符合性分析

v1.2.2 + REV-17 的目标分层是：

```text
全市场扫描
  ↓
状态判定 focus / watch / reject
  ↓
候选池个股报告
  ├─ watch → lite 报告
  └─ focus → full 报告
  ↓
T+1 早盘确认
  ↓
追加 morning_json / morning_grade / pre_market_state / missing_reason
```

当前产品满足情况如下：

| v1.2.2 / REV-17 层次 | 当前产品实现 | 符合度 |
|---|---|---|
| 全市场扫描结果展示 | 最新结果、结果工作台-全部最新 | ✅ 已覆盖 |
| reject 原因排查 | 最新结果、历史信号、缺失标签、说明 | ✅ 基本覆盖 |
| 候选池筛选 | 结果工作台-今日可看、今日观察池、2568 标注 | ✅ 已覆盖 |
| 盘后决策报告 | daily-selection.md / .html / .json | ✅ 已覆盖 |
| 个股 lite/full 报告 | 当前暂无独立入口，daily-selection.md 可部分承载 | ⚠️ 部分符合 |
| T+1 早盘确认展示 | 当前暂无 morning_grade / pre_market_state / missing_reason 专属展示区 | ❌ 未覆盖 |
| 报告存储层 | 当前未明确 stock_detailed_report 独立表的产品承载 | ❌ 待新增 |
| 对外脱敏 | 部分字段和词汇仍需清理 | ⚠️ 部分符合 |

## 七、建议新增页面 / 入口

建议路径：

```text

```

```text

canonical_status = reject → 不生成报告
```

推荐字段：

| 字段 | 说明 |

| code / name | 股票 |
| trade_date | 报告日期 |
| report_type | lite / full |

| final_score | 综合关注度 |

| explode_status | 起爆段 |
| market_state | 市场状态 |
| morning_grade | 早盘确认结果 |
| missing_reason | 缺失或降级原因 |
| report_status | generated / failed / updated |


