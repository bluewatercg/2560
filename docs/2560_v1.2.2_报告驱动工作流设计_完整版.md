## 一、核心设计理念

### 1.1 真实使用模式

```text
导入数据
  ↓
自动计算（canonical_signal_engine）
  ↓
自动生成标准报告包
  ↓
Skill 读取报告包
  ↓
Skill 输出分析结论
  ↓
你（用户）只看 Skill 的结论
```

### 1.2 主产品 ≠ 页面

- **主产品**：标准化的报告包（Markdown / JSON）
- **辅助产品**：结果中心页面（仅供排查、调试、历史追溯）
- **最终入口**：Skill 分析报告

### 1.3 页面降级为“排查入口”

页面不再作为日常主入口，而是用于：

- 某只股票为什么没进候选池？
- 某个字段为什么缺失？
- 某个批次是否异常？
- 某个标注是否正确？
- 历史信号如何回溯？

## 二、报告包目录结构

每天盘后生成一个以交易日期命名的目录，包含以下文件：

```text
reports/YYYY-MM-DD/
├── 01_daily_selection.md          # 盘后决策报告（原 daily-selection.md）
├── 02_focus_full_reports.md       # focus 全维度报告
├── 03_watch_lite_reports.md       # watch 简版报告
├── 04_scan_summary.json           # 全市场扫描汇总（审计用）
├── 05_focus_watch_list.json       # focus + watch 基础清单
├── 06_reject_summary.json         # reject 按原因汇总
├── 07_field_audit.json            # v1.2.2 核心字段分布审计
├── 08_skill_input.md              # Skill 盘后输入报告（核心）
├── 09_morning_confirm.md          # 次日早盘确认报告（早盘生成）
└── 10_skill_morning_input.md      # Skill 早盘输入报告（早盘生成）
```

> 所有文件均在同一目录下，可通过 `trade_date` 定位。

## 三、各文件详细规格

### 3.1 `01_daily_selection.md`

- **内容**：原 daily-selection.md 的标准化版本，包含市场量化模型、热点主线、候选池、交易计划等。
- **定位**：面向人工阅读的盘后总报告。
- **生成时机**：盘后扫描完成后。

### 3.2 `02_focus_full_reports.md`

- **对象**：`selection_status = focus` 的所有股票
- **内容**：每只股票的全维度分析（结构、量能、起爆段、压力、5m、KDJ/MACD、环境、主线、位置、风控、综合结论）
- **格式**：Markdown，按股票分节。
- **用途**：Skill 深度分析的主素材，也可人工阅读。

### 3.3 `03_watch_lite_reports.md`

- **对象**：`selection_status = watch` 的所有股票
- **内容**：简版报告（基础信息、结构、量能、起爆段、主线、风险、观察触发条件）
- **格式**：Markdown，按股票列表形式。
- **用途**：Skill 判断是否有可上调为重点观察的标的。

### 3.4 `04_scan_summary.json`

- **内容**：全市场扫描结果的轻量汇总，不含逐股详情。
- **字段**：

```json
{
  "trade_date": "YYYY-MM-DD",
  "batch_id": "20260609042344",
  "total_stocks": 5000,
  "distribution": {
    "selection_status": {
      "focus": 12,
      "watch": 35,
      "reject": 4953
    },
    "explode_status": { "normal": 120, "warm": 80, "acceleration": 15, "overheat": 30 },
    "market_state": "rebound",
    "hot_topic_strength": { "strong": 2, "medium": 5, "weak": 20, "none": 4973 },
    "position_in_hot_topic": { "leader": 3, "strong": 8, "follower": 12, "edge": 4977 }
  },
  "data_quality": {
    "missing_auction_volume_count": 123,
    "missing_avg5_count": 45
  }
}
```

- **用途**：系统审计、Skill 判断整体市场状态。

### 3.5 `05_focus_watch_list.json`

- **对象**：`selection_status IN ('focus', 'watch')`
- **字段**（每只）：

```json
{
  "code": "000001",
  "name": "平安银行",
  "selection_status": "focus",
  "final_score": 0.85,
  "hot_topic_strength": "strong",
  "position_in_hot_topic": "leader",
  "explode_status": "normal",
  "market_state": "rebound"
}
```

- **用途**：供 Skill 快速读取候选池基本信息，决定深入分析哪些。

### 3.6 `06_reject_summary.json`

- **对象**：`selection_status = reject`（以及未入选的 hold 等）
- **内容**：按原因汇总的统计，不逐票展开。

```json
{
  "total_reject": 4953,
  "by_reason": {
    "volume_weak": 1200,
    "explode_overheat": 800,
    "hot_topic_weak": 1500,
    "position_edge": 1000,
    "market_state_risk_off": 300,
    "data_missing": 153
  }
}
```

- **用途**：快速了解淘汰大头，无需逐票分析。

### 3.7 `07_field_audit.json`

- **内容**：v1.2.2 核心字段的完整性检查。

```json
{
  "fields": {
    "recent_3d_pct": { "missing_count": 0, "out_of_range_count": 12 },
    "kdj_j": { "missing_count": 45 },
    "macd_hist": { "missing_count": 45 },
    "hot_topic_strength": { "missing_count": 200 },
    "position_in_hot_topic": { "missing_count": 250 }
  },
  "data_sources": {
    "auction_volume": { "available": true, "last_update": "2026-06-09 09:25:00" }
  }
}
```

- **用途**：数据质量监控，Skill 判断是否因数据缺失导致误判。

### 3.8 `08_skill_input.md`（核心）

- **定位**：盘后 Skill 的唯一输入。
- **生成规则**：该文件仅包含盘后可得数据，不包含次日集合竞价信息。

```markdown
# 2560 盘后 Skill 输入报告

## 1. 市场环境
- market_state: rebound
- environment_score: 1.0
- 涨停家数: 45，上涨比: 68%

## 2. 候选池概览
- focus 数量: 12
- watch 数量: 35
- 按 final_score 前 5 的 focus 列表（代码、分数、主线强度、个股位置）

## 3. focus 全维度明细（仅展示前 5 或全部，可配置）
每只 focus 包括：
- 基础结构（距均线%、均线方向）
- 量能（5/60 关系、金叉兜底）
- 起爆段（近3日涨幅、状态）
- 30m 压力距离%
- 5m 确认状态
- KDJ/MACD 信号
- 热点主线强度、个股位置
- 风控区间（入场区、风险控制价）
- 综合评分及理由

## 4. watch 简版明细（仅列出可能有升级机会的）
- 按 final_score 排序，筛选 hot_topic_strength in (strong, medium) 且 explode_status in (normal, warm)
- 每只给出：代码、分数、主线、位置、风险摘要

## 5. reject 按原因汇总（仅统计，不逐票）
- 各原因数量及占比

## 6. 数据质量提示
- 缺失字段提醒（如竞价历史不足、avg5 缺失等）

## 7. 明日早盘需验证的关键点
- 对每个 focus，列出需关注的竞价条件（放量要求、理想缺口范围）
```

### 3.9 `09_morning_confirm.md`

- **生成时间**：T+1 日 9:25~9:30
- **内容**：面向人工阅读的早盘确认报告，展示昨日 focus/watch 的竞价表现、morning_grade、pre_market_state、missing_reason。
- **格式**：Markdown 表格。

### 3.10 `10_skill_morning_input.md`

- **定位**：早盘 Skill 的唯一输入。

```markdown
# 2560 早盘 Skill 输入报告

## 1. 早盘市场环境
- pre_market_state: pre_rebound
- 集合竞价指数涨幅: 0.35%

## 2. 昨日候选池早盘确认结果
- 按 morning_grade 分组：
  - high: 代码列表（竞价放量+理想缺口）
  - upgrade_high: 代码列表（watch 升级）
  - normal_cautious: 代码列表（大幅高开需谨慎）
  - hold: 代码列表（无显著放量）
  - downgrade: 代码列表（低开/缺口过大）
  - skipped: 昨日无候选（标记）

## 3. 数据缺失说明
- 列出缺失 yesterday_auction_volume 或 avg5 不足的股票，及 morning_grade 降级原因

## 4. 建议操作
- 高度关注: high 列表
- 升级关注: upgrade_high 列表
- 暂时观望: normal_cautious + hold
- 放弃: downgrade 列表
```

## 四、生成时机与接口

### 4.1 盘后报告包生成

**触发方式**：

- 自动：每天 17:30 后（全市场扫描完成且公告/研报拉取完成后）
- 手动：`POST /api/reports/daily-package/new?trade_date=YYYY-MM-DD`

**响应**：

```json
{
  "trade_date": "2026-06-09",
  "batch_id": "20260609042344",
  "status": "generated",
  "files": [
    "reports/2026-06-09/01_daily_selection.md",
    "reports/2026-06-09/02_focus_full_reports.md",
    "..."
  ]
}
```

### 4.2 获取 Skill 输入报告

- **盘后**：`GET /api/reports/skill-input.md?trade_date=YYYY-MM-DD`，返回 `08_skill_input.md` 内容。
- **早盘**：`GET /api/reports/skill-morning-input.md?trade_date=YYYY-MM-DD`，返回 `10_skill_morning_input.md` 内容（仅当 trade_date 是当日且已过 9:30）。

### 4.3 获取报告包任意文件

```text
GET /api/reports/daily-package/file?trade_date=YYYY-MM-DD&filename=08_skill_input.md
```

### 4.4 早盘确认生成

**触发方式**：

- 自动：每天 9:30 后执行一次（仅当昨日有 focus/watch）
- 手动：`POST /api/reports/morning-confirm/new?trade_date=YYYY-MM-DD`（trade_date 应为当日）

**生成文件**：`09_morning_confirm.md` 和 `10_skill_morning_input.md` 写入 `reports/YYYY-MM-DD/`。

## 五、与现有页面的关系（降级为辅助）

| 页面/模块 | 角色转变 |
|---|---|
| 结果工作台 | 仅用于调试、快速查看某日焦点，不再作为主入口 |
| 最新结果 | 排查某只股票为什么没入选，检查 selection_status 和 missing_tags |
| 信号中心 | 历史事件追溯，分析过去命中/未命中的原因 |
| 今日观察池 | 预览候选池，但主流程应依赖报告包 |
| 2568 标注 | 复核标注逻辑是否合理 |
| 结果统计 | 策略复盘时使用 |

> **原则**：页面不阻塞主工作流。主工作流完全通过报告包 + Skill 完成。

## 六、Skill 输入/输出规范（建议）

### 6.1 Skill 输入（盘后）

- **必须输入**：`08_skill_input.md` 的内容（全文）
- **可选输入**：`05_focus_watch_list.json`（如需结构化数据）

### 6.2 Skill 输出（盘后）

Skill 应输出至少以下内容：

```markdown
# 2560 盘后分析结论

## 明日重点观察
- 代码、名称、关键逻辑、理想竞价条件

## 需进一步确认的 focus（风险点）
- 代码、风险描述

## watch 中可考虑上调的标的
- 代码、上调理由

## 市场整体判断
- 是否适合开新仓
- 仓位建议
```

### 6.3 Skill 输入（早盘）

- **必须输入**：`10_skill_morning_input.md`

### 6.4 Skill 输出（早盘）

```markdown
# 2560 早盘确认结论

## 高度关注（high）
- 列表及操作建议

## 升级关注（upgrade_high）
- 列表及操作建议

## 降级/放弃（downgrade）
- 列表及原因

## 数据缺失影响
- 哪些票因数据缺失无法确认
```

## 七、验收标准

1. **盘后报告包自动生成**
   - 每天 17:30 后，`reports/当天/` 目录下生成 8 个文件（01~08）。
   - `08_skill_input.md` 内容完整，包含 focus 全维度、watch 简版、reject 汇总、数据质量提示。

2. **早盘报告包自动生成**
   - 每天 9:30 后，若昨日有 focus/watch，则在 `reports/当天/` 下追加 `09_morning_confirm.md` 和 `10_skill_morning_input.md`。
   - 若昨日无候选，则跳过并记录日志。

3. **Skill 可独立读取报告包**
   - 通过 HTTP 接口获取 `08_skill_input.md` 和 `10_skill_morning_input.md` 的内容，无需登录页面。

4. **页面不干预主流程**
   - 即使页面不可访问，报告包生成和 Skill 分析仍可独立运行。

5. **报告包内容与算法结果一致**
   - 随机抽查 focus/watch 个股报告，确保数据与 `structure_2560_analysis` 及 `morning_confirm_daily` 表一致。

## 八、最终定义

> **2560 v1.2.2 的主产品不再是“结果中心页面”，而是标准化的报告包。**
> **用户的主入口是 Skill 分析结论，而非页面浏览。**
> **页面仅作为排查和调试的辅助工具，不承载决策主流程。**
> **每天系统自动完成：数据导入 → 扫描计算 → 报告包生成 → Skill 分析 → 用户获得结论。**
